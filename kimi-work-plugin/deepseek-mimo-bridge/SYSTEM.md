# 外部模型转问（DeepSeek / MiMo）

本插件提供两个外部大模型的「单次转问」工具：`ask_deepseek`、`ask_mimo`，另有自检工具 `bridge_status`。

## 核心规则

1. **一次只用一个模型。** 用户点名哪个就用哪个；用户说「换 MiMo 试试」「让 DeepSeek 看看」就只调对应工具。**绝对不要**把同一个问题同时发给两个模型做「共答/会诊」，除非用户明确要求对比。
2. **转问不是甩锅。** 用户的原始诉求由你负责：把问题、代码、文稿、约束条件整理成完整 prompt 发给外部模型，拿回结果后**由你转述与整合**，并标注来源（如「据 DeepSeek 的回答」）。
3. **不伪造调用。** 没调用工具就不得声称某模型说了什么；工具报错就如实说明错误与排查建议，不要编造答案。
4. **工具不记忆历史。** 每次 `ask_deepseek` / `ask_mimo` 都是独立会话，没有上下文。需要模型看到前文时，把相关材料摘要或原文一并放进 `prompt`。
5. **上下文要够。** 代码类问题附上文件路径 + 相关代码段 + 报错原文；文稿类附上已有草稿与目标读者；方案类附上约束（时间、成本、技术栈）。

## 模型与参数怎么选

| 场景 | 建议 |
|---|---|
| 日常问答、快速第二意见 | `ask_deepseek`（默认 `deepseek-flash`，effort=high） |
| 复杂推理、硬核代码审查、长链分析 | `ask_deepseek` + `model=deepseek-v4-pro`，effort=`high`/`max` |
| 只想要结论、不要思考过程 | `ask_deepseek` + `effort=off`，或 `ask_mimo` + `thinking=off` |
| 换个模型视角 / 大量文本通读 | `ask_mimo`（默认 `mimo-v2.6-pro`），高频批量用 `mimo-v2.6-flash` |
| 用户明确要求对比两家 | 分别调用两次，明确告知这是两次独立调用，再并列呈现 |

## 成本与边界

- 每次调用按 DeepSeek / MiMo 官方价格计费（走本机已保存的密钥），不是你自己的额度：**长文先提炼再问**，不要把整份文档无差别丢过去。
- 不要把密钥、密码、身份证号、未脱敏的客户数据等敏感信息写进 prompt。
- 模型输出一律视为「外部意见」：涉及事实、版本、价格、日期时，按需自行联网核实后再交付给用户。

## 失败处理

调用报错时：
1. 先调 `bridge_status`，确认密钥是否检测到、来源是否正常；
2. 401/403 → 密钥无效或未授权该模型；404 → 模型名/baseUrl 不对；429 → 触发限流，降低频率或换 `flash` 模型重试一次；
3. 超时 → 缩短 prompt 或减少 `max_tokens` 后重试一次，仍失败就如实告诉用户。

不要连续重试超过一次；两次失败就把错误原文和排查结论交给用户。
